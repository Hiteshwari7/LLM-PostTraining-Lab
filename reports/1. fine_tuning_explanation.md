# Fine-Tuning, Explained: From Pretraining to a Domain Tutor

## 1. Where fine-tuning sits in an LLM's life

A model like Llama-3.2 is built in layers, each one narrowing what the model is good at:

```
Pretraining  →  Continued Pretraining  →  Supervised Fine-Tuning (SFT)  →  Preference Alignment (DPO/RLHF)
(general      (domain vocabulary)        (instruction-following          (response quality &
 language                                 format & behavior)              human preference)
 & world
 knowledge)
```

Each stage narrows the model's behavior without throwing away what came before later stages build *on top of* earlier ones, they don't replace them.

## 2. Continued Pretraining (Stage 1)

**What it is:** more of the *same kind* of training the base model already went through i.e next-token prediction on raw, unlabeled text ,just on a narrower, domain-specific corpus instead of "the whole internet."

**What it's for:** shifting the model's internal representations toward a domain's vocabulary, phrasing, and typical sentence structure, in this project, the language used to describe Transformers, LoRA, QLoRA, SFT, DPO, RLHF, and alignment.

**What it does *not* do:** it doesn't teach the model to follow instructions or hold a conversation, that's the next stage's job. A model straight out of continued pretraining is still just "good at completing domain text," not "good at answering domain questions."

## 3. Supervised Fine-Tuning — SFT (Stage 2)

**What it is:** training on curated `{instruction, response}` pairs, formatted through the model's chat template, so the model learns the *shape* of a good answer: read a question, produce a direct, well-structured response.

**What it's for:** turning a text-completion engine into something that behaves like an assistant — this is the stage that makes "What is LoRA?" reliably produce an explanation rather than, say, a list of similar-sounding questions (which is what a raw continued-pretraining model might do).

**Why LoRA/QLoRA here:** SFT technically *can* update every parameter in the model ("full fine-tuning"), but that requires enormous GPU memory and storage per checkpoint. LoRA/QLoRA make SFT affordable on a single free-tier GPU by training a small adapter instead — see `lora_explanation.md` for the mechanics.

## 4. Why this project separates Stage 1 and Stage 2

It would be possible to skip continued pretraining and go straight from the base model to SFT. Keeping them separate here is deliberate, for demonstration purposes:

- It mirrors how real post-training pipelines are structured (domain adaptation, *then* instruction tuning, *then* alignment).
- It makes the effect of each stage individually visible when you compare checkpoints in `03_Evaluation.ipynb` — you can see how much continued pretraining alone changes vocabulary use, versus how much SFT changes response *structure*.

## 5. What comes after SFT

SFT gets a model to produce *plausible, well-formatted* answers — but "plausible" isn't the same as "the answer a person would actually prefer." That gap is what Stage 3 (DPO) addresses — see `dpo_explanation.md`.
