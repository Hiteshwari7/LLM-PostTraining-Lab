# Fine-Tuning, Explained: From Pretraining to a Domain Tutor

## 1. Where fine-tuning sits in an LLM's life

A model like Llama-3.2 is built in layers, each one narrowing what the model is good at:

```
Pretraining    →  Supervised Fine-Tuning (SFT)  →  Preference Alignment (DPO/RLHF)
(general            (instruction-following          (response quality &
 language             format & behavior)              human preference)
 & world
 knowledge)
```

Each stage narrows the model's behavior without throwing away what came before i.e  later stages build *on top of* earlier ones, they don't replace them.

## 2. Supervised Fine-Tuning — SFT (Stage 1)

**What it is:** training on curated `{instruction, response}` pairs, formatted through the model's chat template, so the model learns the *shape* of a good answer: read a question, produce a direct, well-structured response.

**What it's for:** turning a text-completion engine into something that behaves like an assistant — this is the stage that makes "What is LoRA?" reliably produce an explanation rather than, say, a list of similar-sounding questions (which is what a raw continued-pretraining model might do).

**Why LoRA/QLoRA here:** SFT technically *can* update every parameter in the model ("full fine-tuning"), but that requires enormous GPU memory and storage per checkpoint. LoRA/QLoRA make SFT affordable on a single free-tier GPU by training a small adapter instead — see `lora_explanation.md` for the mechanics.

## 3. What comes after SFT

SFT gets a model to produce *plausible, well-formatted* answers  but "plausible" isn't the same as "the answer a person would actually prefer." That gap is what Stage 3 (DPO) addresses..see `dpo_explanation.md`.
